# STRATO: Equation-to-Code Traceability Matrix for the Five-Layer BTCS Solver

**Status.** This is Document 4 of directive Section 9. It maps every numbered equation of [Document 2](02_final_formulation.md) ("D2") to the routine of [Document 3](03_rust_pseudocode.md) ("D3") that implements it, to the Rust item that is planned to hold it, and to the test that will check it.

**The solver does not exist yet.** Every module, function and test named below is *planned*. Nothing in this table claims that an item has been written, compiled or run, and no test outcome is recorded. The column "Implemented in" is empty by design: it is filled, with the commit that first contains the item, by the agent that writes the solver, and a row may be filled only when its test exists and passes without a loosened tolerance.

## 1. How to read the tables

- **Routine** is a pseudocode routine of D3 (PS-01 to PS-19).
- **Planned Rust item** is `module::item`, where `module` is a path under `src/` of the existing crate (for example `numerical::grid`). The proposed layout is D3 Section 1.3.
- **Test** names the planned test and the independent reference it uses. Two kinds of location appear:
  - unit tests inside the module, written `module::tests::name`;
  - integration tests `btcs_verification::name` in `tests/btcs_verification.rs`, the driver `examples/verify_btcs.rs` (planned marker line `BTCS_VERIFICATION PASS`), regression tests `btcs_regression::name` in `tests/btcs_regression.rs`, and wrapper parity tests in `crates/strato-wasm/tests/parity.rs`.
- **References that do not depend on the BTCS code.** A test is only as strong as its reference. The references named are: (a) values evaluated by hand or by exact rational arithmetic *inside the test* from the formula of D2, for a small grid with one interval per material and for a grid with several; (b) a dense Gaussian elimination written in the test module (no new dependency); (c) the independent Sturm-Liouville solver `analytical::sturm_liouville::ModalRelease` (retained, no BTCS code); (d) the closed form of the homogeneous sphere (a series in `examples/verify.rs` today); (e) the single-mode exact solution $C(r,t) = \exp\left(-\pi^2 D t/\left(R\right)^2\right)\sin\left(\pi r/R\right)/\left(\pi r/R\right)$ for one material, derived in the verification plan; (f) the value of the release fraction of the synthetic case from a separate-language script that the repository already pins. A test that compares the solver with its own earlier output is a regression test and is labelled so; it is not evidence of correctness.
- **No tolerance is fixed in this document.** Each tolerance is set by the author of the test, before the first run, from an operation count or rounding analysis (floating-point checks) or from the observed refinement sequence (discretisation checks), and recorded with the reason. A failing test is reported and stays failing; no tolerance is relaxed to make a test pass (directive Section 11).
- **Numerical verification is not experimental validation.** None of these tests compares with a measurement.

## 5. Gaps and notes

1. **Independent references that do not yet exist.** The Sturm-Liouville module returns the release fraction only. The profile-level tests (centre value in (F12), single-mode checks in (F26), P8a, P11, P13) use the closed forms (d) and (e), which are implemented inside the tests. A profile function for the layered series, if wanted, is new work in `analytical` and needs its own review; this table does not assume it.
2. **Phase G.** The generation, decay and temperature equations are not in D2 and therefore have no row. When they are derived and reviewed they add rows (and extend the balance row (F29)); until then the baseline rows above are complete.
3. **Property P14 and the order bands.** The order bands used in the convergence tests are set before the first run (verification plan, rule R3) and are not changed after seeing results; a changed band needs a recorded reason.
4. **Cross-reference in D2.** The introduction of D2 Section 5 cites (F15) for the statement that $C_N^{j+1}$ is not an unknown. The condition is (F18). This matrix and D3 use (F18). The document D2 itself has not been changed.
5. **Nothing in this table is a result.** The "Implemented in" column and every statement of the form "the test passes" are absent on purpose.
